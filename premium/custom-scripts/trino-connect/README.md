# trino-connect

Methodology for a Python helper that connects to a Trino / Starburst cluster. Use this as a template — adapt the keychain entry name, host, and example query to your product.

## What it does

A typical `trino_connect.py` helper:
- Reads Trino credentials from the OS keychain (macOS Keychain, `secret-tool` on Linux, etc.) — never hardcoded, never committed.
- Opens a connection to the Trino / Starburst coordinator.
- Exposes a `run_query(sql)` function returning a list of dicts (one per result row).

The actual `trino_connect.py` is **not** committed to this repo. Each workspace adds its own copy alongside this README, configured for its cluster and credentials. The companion `data-warehouse-connect/README.md` covers the broader credential-hygiene pattern across warehouse types.

## Setup template

Keychain entry (one time, name it after your cluster):

```bash
security add-generic-password -a "$USER" -s "<your-cluster-name>" -w 'your-trino-password'
```

Install Python dep:

```bash
pip install trino
```

## Usage template

```python
from trino_connect import run_query

rows = run_query("""
    SELECT <your_partition_column>, <your_dimension>, COUNT(*) AS cnt
    FROM <your_catalog>.<your_schema>.<your_table>
    WHERE <your_partition_column> = DATE '<recent-date>'
      AND <your_product_filter>
    GROUP BY 1, 2
    ORDER BY cnt DESC
    LIMIT 20
""")

for row in rows:
    print(row)
```

## Inputs
- `sql` — a Trino-compatible SQL string. See your product's `knowledge/data-sources/<source>/gotchas.md` for dialect pitfalls.

## Outputs
- A Python list of dicts, one per result row. Column names match the SELECT output.

## What lives where

- **This file (methodology)** — workspace-agnostic, committed.
- **`trino_connect.py` (the actual helper)** — workspace-specific, generated by `/onboard` or hand-written when wiring the data source. Lives next to this README in your clone.
- **Cluster credentials** — never in this repo. Always in the keychain / vault / `.env` (gitignored).
